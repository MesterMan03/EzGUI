# EzGUI 3.0 test report

Everything below was executed against a real Minecraft 1.21.1 server
(`minecraft-1-21-1-test-server`), driven by a headless protocol bot
(`minecraft-protocol`, version 1.21.1), with all assertions read back from server truth
over RCON. Nothing is simulated in JavaScript.

## How to run

```bash
./lib/deploy.sh            # copy the pack into the server's datapack folder
node probe/reload_errors.js  # fresh /reload → expect "NO ERRORS"
node probe/clean.js         # kill leftover containers/items
node test/e2e.js            # the end-to-end suite
cd ../EzGUI/tools && npx tsx src/lint.ts ../data
```

## Bugs the suite caught (and what the fix was)

1. **Item components were emitted without brackets.** `c:` stores the suffix, the
   printer has to re-add `[…]`. Symptom: `Invalid ID at position 65`.
2. **Over-escaped SNBT strings.** A single-quoted SNBT string only escapes `\` and `'`;
   escaping `"` inside it produced `Invalid escape sequence` and a 146-character command
   that silently failed. `sq()` in `guigen.ts` now escapes exactly those two.
3. **A macro never sees a value written in the same call.** `state_pick` → `emit` in one
   function printed the previous frame. Every step is now prep + print.
4. **A missing macro key aborts the whole function.** One-line `unless data` seeding per
   key turned out to be unreliable once `ctx` was large; `core/seed` now does small
   `data merge`s per entry point.
5. **Seeding inside `core/ctx` wiped prepared values.** `core/ctx` runs in every loop;
   seeding moved to `core/seed`, which only runs at entry points.
6. **`probe` built as a raw token.** `data modify … set value *[custom_data~…]` is not
   NBT; the item predicate is now written inside the real `items` command.
7. **Item/score cost branch always took the item path.** The flattened `ci` key is always
   present (seeded empty string), so `if data … ci` always won. Dispatch now tests the
   definition: `cost[$(idx)].item`.
8. **The entry count never reached its score.** `cost_item`/`cost_score` compare against
   `#need`, which was only ever written into storage.
9. **Ad-hoc `execute if score #k > #c` does not exist.** It parsed as a *value* `#k`; the
   comparison silently never ran.
10. **Every scored widget was treated as a toggle.** `load_w` copied the score into the
    toggle slot, so cycle/radio/counter widgets rendered the OFF/ON pair. Kind markers
    are now emitted per state (`toggle`, `cycle`, `radio`, `indicator`, `progress`).
11. **Page transitions looked like clicks.** Click detection compared "the state id the
    score now selects"; a change of menu/page made every slot mismatch. The stamp carries
    `m`/`p` and detection compares the stamp.
12. **Repainting every tick dropped real clicks.** The client resynced its window copy
    continuously and the server dropped the click packets. The repaint is now full on a
    handled click and otherwise limited to cells with live text or several states.

## Known limits

* Live text refreshes once a second, not every tick — a deliberately narrow write so the
  window stays stable for clicks.
* The bot drives clicks through `window_click`; the datapack never reads mouse buttons,
  it only sees the resulting container state.
* `ezgui.mid` is sticky per player by design (it remembers the last menu).
